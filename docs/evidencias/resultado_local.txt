### VUL001 - SQLi en login (bypass de autenticacion)
  original : payload ' OR '1'='1' -- -  -> SESION ABIERTA sin credenciales
  corregida: mismo payload               -> sin sesion (bloqueado)

### VUL002-VUL005, VUL020 - SQLi en parametro id / validacion de entradas
  original  index.php?id=0 UNION SELECT 1-- -  -> HTTP 200  (inyeccion aceptada)
  corregida index.php?id=0 UNION SELECT 1-- -  -> HTTP 404  (rechazado)

### VUL006 - SQLi en mostrar_carrito.php
  original  ?id=1 OR 1=1     -> HTTP 200
  corregida ?keyid=1 OR 1=1  -> HTTP 404   | ?keyid=1 -> HTTP 200

### VUL009 - Almacenamiento de contrasenas
  original  (texto plano):
    admin@gmail.com  ->  admin01
    alondra@gmail.com  ->  alondra01
  corregida (hash bcrypt):
    admin@gmail.com  ->  $2y$12$ODh076...  (60 chars)
    alondra@gmail.com  ->  $2y$12$mk.wpA...  (60 chars)

### VUL010 / VUL014 - XSS almacenado y autorizacion en servidor
  corregida: POST a grcomentarios SIN sesion -> HTTP 403  (requiere login)
  corregida: con sesion, <script> se guarda pero en el HTML aparece:
      &lt;script&gt;alert(1)&lt;/script&gt;

### VUL011 - CSRF + metodo en login (corregida)
  POST sin token -> HTTP 403   |   GET -> HTTP 405

### VUL012 - CSRF en comentarios (corregida, con sesion)
  POST sin token -> HTTP 403

### VUL013 / VUL007 / VUL016 - Carrito: CSRF, SQLi y logica de negocio (corregida)

  op=1 iditems=3 (item eliminado)           -> HTTP 404  (VUL016)
  op=1 iditems=5 (item visible)             -> HTTP 200
  op=9 (operacion invalida, VUL020)         -> HTTP 400
